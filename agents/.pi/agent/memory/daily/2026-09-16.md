## Diagnóstico: subagentes abortados vía Paseo (#bug #infra)

- **Causa raíz**: cada "Subagent was aborted" en la sesión coincide 1:1 (~10 s después) con un "Cancel request received" en `~/.paseo/daemon.log`. La app Paseo (desktop/móvil) envía cancel cuando se escribe un mensaje mientras el agente corre (steer/replace del turno) o se presiona Stop → mata el turno padre → el AbortSignal mata a los procesos hijos `pi -p --no-session` de los subagentes.
- **Por qué "Parallel: 3/3 done" nunca resuelve**: bug de Paseo 0.8.0 — `AgentRunCancellationError: "active run cancellation was not acknowledged"` + `"Timed out interrupting session during cancel"`. El daemon no logra interrumpir pi cuando está bloqueado en un tool call largo (subagent); el turno queda zombi: la UI muestra "done" pero el resultado nunca llega.
- Confirmado upstream: PRs getpaseo/paseo #4273 (interrupción marca subagentes como cancelados) y #3091 (esperar acknowledgment de cancelación) — área activa de fix.
- **Regla**: cuando Paseo muestre "Parallel: N/N running", NO enviar mensajes ni Stop hasta que el turno termine solo; cualquier interacción cancela y pierde el trabajo delegado (los subagentes corren con `--no-session`, sin persistencia).
- Los 3 aborts de la sesión pc-metrics (23:52, 23:56, 00:08 UTC) mataron a los researchers; solo `ai-watcher-design.md` alcanzó a escribirse antes del abort.
