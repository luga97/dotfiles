# Infra: identidad y reconstrucción del monitor

El perfil `infra` de Hermes se ejecuta en home server. En este directorio se versionan su `SOUL.md`, la fuente de `infra-monitor.py` y una instantánea de las instrucciones del job horario `infra-monitor-prompt.txt`, sin credenciales. La configuración real, los cron jobs y la memoria del perfil son locales a `~/.hermes/profiles/infra` y no se sincronizan por Git. La copia puntual del 9 de noviembre de 2026 no forma parte de la configuración permanente.

## Monitor existente

El job `[bot:infra] Discos y respaldos` usa `infra-monitor.py` con `--script` en modo agente cada 60 minutos y entrega configurada `bot-chat,telegram`. Informa de todas las incidencias actuales en cada ejecución, incluidos estados desconocidos; devuelve `[SILENT]` si todo está sano. El script consulta la ocupación de `/` y `pz-backup.timer`/`pz-backup.service`; no cubre todos los servicios ni verifica la restauración. Un fallo automático anterior a la reconexión de Drive no implica una falla nueva; un mensaje encolado no prueba recepción. Un monitor dentro del servidor no puede avisar de la propia caída del servidor.

No usar `--monitor-script` para esta rutina: su supresión por cambios no cumple la política de recordatorios horarios. El prompt versionado es una instantánea y contiene contexto fechado: cotejarlo y actualizarlo con evidencias actuales antes de reconstruir; no asumir que el estado del 8 de noviembre siga vigente.

## Recuperación manual (no ejecutar en un perfil sano)

1. Verificar si ya existen el perfil y el job con `hermes profile list` y `hermes -p infra cron list`; no crear duplicados ni restaurar ciegamente trabajos históricos. Instalar Hermes y autenticar el proveedor por el flujo oficial sin copiar credenciales entre máquinas. Crear el perfil solo si falta: `hermes profile create infra --description 'Diagnóstico de infraestructura, discos, respaldos y servicios; intervenciones solo con autorización de Luis.'`.
2. Revisar el SOUL local existente y conservarlo antes de reemplazarlo. En home server enlazar únicamente el SOUL aprobado: `ln -s ~/dotfiles/services/services/hermes/infra/SOUL.md ~/.hermes/profiles/infra/SOUL.md`. No sobreescribir un archivo existente a ciegas. Si se instala en otro host, ajustar primero las rutas y su función.
3. Instalar el script como **archivo regular** en el directorio del perfil, no como symlink externo: `install -Dm700 ~/dotfiles/services/services/hermes/infra/infra-monitor.py ~/.hermes/profiles/infra/scripts/infra-monitor.py`. Revisar permisos y ejecutar el script directamente para verificar la lectura, sin disparar el job ni enviar mensajes.
4. Revisar el prompt versionado y los destinos; configurar conexiones y autorización por medios privados, sin añadir `.env`, tokens, OAuth ni claves a Git. Consultar `hermes -p infra cron create --help` de la instalación vigente. Solo tras comprobar que no existe la rutina, recrearla inicialmente pausada con `--name '[bot:infra] Discos y respaldos'`, `--script infra-monitor.py`, `--deliver 'bot-chat,telegram'`, intervalo `60m` y el prompt actualizado. Ejemplo, tras revisar el archivo: `hermes -p infra cron create 60m "$(< ~/dotfiles/services/services/hermes/infra/infra-monitor-prompt.txt)" --name '[bot:infra] Discos y respaldos' --script infra-monitor.py --deliver 'bot-chat,telegram' --paused --paused-reason 'Revisar antes de activar'`.
5. Comprobar que el job quedó pausado y que se resolvieron el script y ambos destinos. Acordar las pruebas de alerta, repetición, recuperación, silencio y estados desconocidos sin provocar fallos reales ni avisos duplicados; autorizar activación por separado. Comprobar entrega real en cada destino, no solo encolado.

No versionar `config.yaml` completo, `.env`, `auth.json`, bases de datos, conversaciones ni tokens; pueden contener datos privados. La identidad sola no restaura memoria, conversaciones, tablero Kanban, credenciales ni trabajos programados. El script instalado es una copia: tras cambiar su fuente hay que instalarla expresamente con autorización y verificarla; actualizar Git no modifica automáticamente el monitor activo.
